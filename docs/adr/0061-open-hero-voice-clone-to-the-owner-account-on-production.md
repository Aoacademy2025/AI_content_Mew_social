# ADR 0061: Open Hero Voice Clone to the owner account on production

Status: accepted — 2026-09-07 (supersedes the production NO-GO half of ADR 0060)

Hero Voice Clone may run on production for exactly one cohort: the product owner's own account, whose reference recording is her own voice. The data subject herself accepts sending that recording to the pinned clone-only RunPod worker (image digest, source revision and model manifest are still the exact five deployment inputs of ADR 0060; nothing routes through the stock endpoint or any fallback). The decision is carried by one explicit deployment variable, `HERO_VOICE_CLONE_PRODUCTION=1`, which opens the human-data gate as `owner-consent-production-gate`; it never combines with the isolated canary execution mode, and without it production stays fail-closed byte-for-byte as before. Access remains the intersection of `HERO_VOICE_CLONING_ENABLED=1`, the internal-tester allowlist and `OMNIVOICE_ALLOWED_USER_IDS`, so no customer can reach the transport. The endpoint is persistent but scale-to-zero (no idle cost, one worker, cold start of a few minutes), spend is bounded by the existing per-clip settlement, and rollback is unsetting that one variable. Every generated part still passes the ASR content gate (dropped and inserted runs), and Story Film, Video Editor, MCP and the stock Hero Voice preset are untouched. Opening the transport to any other person's voice remains a separate rights decision.
