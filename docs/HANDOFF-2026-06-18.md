## What Changed

### 1. Playback Insights

PR #91 added reliable client playback events from actual `<video>` lifecycle:
- session started
- first frame
- canplay
- waiting/stalled
- error
- source route/page/video id

Purpose: measure whether preview/gallery stutter is real, which route it happens on, and whether first frame/buffering is the bottleneck.

### 2. B-roll Insights + Pipeline Run ID

PR #92 added:
- B-roll Resource panel in `/admin/insights`
- fetch-stock server metrics: p95, cache hit, download fail, provider mix, normalize, search/rank/download phase timing
- `pipelineRunId` + `draftId` on editor pipeline telemetry and fetch-stock server telemetry
- funnel switches to run-level counting when `pipelineRunId` exists, with event-count fallback for older data

Important: no render/ffmpeg concurrency increase. The added server cost is lightweight timestamp/metadata telemetry only.

### 3. PROCESSING Stuck / Reconcile

PR #93 uses the existing reconcile system instead of creating a new one.

Existing pieces confirmed:
- `src/lib/video-reconcile.ts`
- `/api/cron/reconcile-processing`
- `/api/admin/videos/reconcile-processing`
- `scripts/reconcile-processing.js`
- PM2 cron entry `reconcile-processing`

Changes in PR #93:
- Admin Insights now has a button to fix output-ready `PROCESSING` jobs.
- Admin action uses `failMissingOutput=false`, so it completes only jobs with valid output and does not fail jobs that are still missing output.
- Cron threshold changed from `180` minutes to `30` minutes, still with `failMissingOutput=0`.

Risk: low. This touches DB status only after validating output URL/file. It does not touch render/ffmpeg execution.

### 4. Telemetry Error Noise

PR #93 separates known benign noise from real errors in `/admin/insights`.

Noise currently recognized:
- browser `play()` interrupted by `pause()`
- `superseded`
- `AbortError` / cancelled / aborted
- opaque browser `Script error.`

Impact:
- Health Score and Top Errors now use real errors only.
- Noise is still visible in a separate section, so we do not hide data.

Risk: low to medium. This changes analytics interpretation, not user workflow. Watch that real errors are not over-classified as noise.

### 5. Remotion Bundle Missing

PR #93 hardens render/burn against:

```text
remotion-webpack-bundle.../index.html does not exist
```

Changes:
- track active Remotion bundle refs in the render cancel registry
- render cleanup and daily cleanup skip active bundle names
- if bundle/index.html missing is detected before composition or during renderMedia, rebuild bundle and retry once
- emit `render_bundle_rebuilt` telemetry when this recovery path runs

Risk: medium because it touches core render path, but it does not raise concurrency. Extra bundle work only happens after a bundle-missing error pattern is detected.
