# Preflight verdict: NOT READY

1. **The reveal bijection does not require condition-matched pairs.** The declared validator requires only one baseline and one candidate per pair and global one-time coverage of all final slots/audio hashes. That permits a baseline for one script/repeat to be paired with a candidate for a different script/repeat, while still satisfying the schema and Acceptance Criteria. The locked preference result would then be invalid. Require every pair to match the same predeclared comparison key (at minimum `scriptId` and `repeatId`, plus the same final `speechText` hash and synthesis settings); randomize only pair presentation order and A/B orientation. Make this predicate part of creation, lock, reveal, and Acceptance Criteria.

2. **A successful run is not acceptance-bound to exactly 44 paid dispatch attempts.** The Fixed Contracts create 44 slots and describe the smoke as slot 27, but Global Constraints say “exactly 44 paid slots maximum” and Acceptance Criteria require only “never exceeds 44.” Early terminal stops correctly need fewer dispatches, but the plan never distinguishes that aborted `NO-GO` case from the completed evidence-run invariant. Define: a completed canary has exactly 44 distinct `/run` dispatch attempts (8 ablation + 18 baseline + 18 candidate), with `final.candidate.script-01.repeat-01` being the one counted smoke and never an additional request; fewer than 44 is allowed only for a terminal aborted `NO-GO`. Assert these counts from the append-only ledger in Acceptance Criteria.

3. **The final `speechText` contract is not fully closed across normalization, baseline, candidate, CER, and pairing.** Task 5 freezes six source scripts byte-for-byte, while `text-normalization-v1` and `combined-v1` use application-produced normalized `speechText`; the plan does not state the six resulting final strings/hashes or explicitly require both final arms to receive identical bytes. This matters especially for the date/currency and English-name scripts. Freeze the source text, final normalized `speechText`, normalizer identity, and their hashes in the pre-payment manifest; require the baseline and candidate slot for each comparison key to have identical final `speechText` bytes/hash, and use that same value as canonical CER expected text.

4. **“Canonical CER” is not reproducible from the pinned inputs given.** Whisper package/model and decoder options are fixed, but the FFmpeg build and exact conversion command/resampler are not, and the evaluator's transitive runtime (notably PyTorch and numerical dependencies/device/determinism settings) is not pinned. A threshold-adjacent output can therefore change transcription and the raw `<=0.10` decision across machines while all listed checks pass. Add an immutable evaluator lock/container identity, exact FFmpeg build and argv, pinned transitive dependencies and execution device/determinism settings, then require a repeatability fixture/readback from the same artifact used for the paid evaluation.

5. **The commitment bytes and close-recovery terminal state each have two permissible interpretations.** The plan precisely canonicalizes the reveal plaintext but does not define the ciphertext-envelope schema, binary/base64 encoding, or canonical serialization whose bytes are hashed and pushed. Separately, deletion says the database row/state may be “deleted or finalized,” while the review-close invariant requires the run to remain `closed`; recovery behavior and evidence differ between those outcomes. Define one versioned ciphertext-envelope schema and byte serialization for commit/lock/reveal verification. Also define per operation whether the authoritative row is deleted or retained as a sanitized terminal receipt (`voice delete`, `review close`, `account hard-delete`), and make reconciliation plus crash tests assert that single outcome after the pre-move intent.
