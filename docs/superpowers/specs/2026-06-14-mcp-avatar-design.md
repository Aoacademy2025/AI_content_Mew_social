# MCP avatar support — design spec (2026-06-14)

Wire **avatar (HeyGen)** support into the MCP `create_video_job` tool. Today the MCP
pipeline renders **without** avatar (`src/lib/mcp/orchestrator.ts` hardcodes
`avatarModel: "none"`). The web app already supports avatar fully; this spec reuses the
existing web endpoints headlessly from the MCP worker — **no fork** of the render logic.

## Goal & scope

- **v1 modes:** `full`, `bookend`, `bookend-both` (all three).
- **Input:** `generate` only — HeyGen avatar via `avatarId` (default the user's saved
  `User.heygenAvatarId`, overridable per call). No `direct` (upload) mode in v1.
- **Voice:** the avatar lip-syncs to the **TTS audio already generated by the pipeline**
  (Gemini/ElevenLabs), not a HeyGen voice.
- **Gate:** PRO/BUSINESS (same as `create_video_job` today) **and** requires a HeyGen key
  + a resolvable `avatarId`.
- **Architecture:** Approach A — sequential, avatar steps run **after** base render,
  factored into a new `src/lib/mcp/avatar-steps.ts`. Parallel (avatar-gen ∥ base render)
  is explicitly out of scope for v1.

Out of scope: `direct`/upload avatar, exposing scale/offset layout, `rembg` composite,
parallel generation, `rerun_video_step`.

  `text|audioUrl, avatarId, voiceId, greenScreen, scale, offsetX, offsetY`; reads

- Poll: `src/app/api/videos/poll-avatar/route.ts:21-83` → `{status, videoUrl, ...}` via

- Composite (FFmpeg chromakey overlay): `src/app/api/heygen/composite/route.ts` — modes
  `chromakey` (default `:110-189`), `rembg`, `direct`; timing handling `:509-568`;
  `bookend-both` split slices bg into 3 segments via `applyBookendBothSplit()` (`:329-460`).
- Trim audio for bookend: `src/app/api/videos/trim-audio/route.ts:38-108` — intro (first N),
  tail (last T), or intro+tail.
- Web UI modes/state: `src/app/(dashboard)/video-creator/page.tsx:360-362`
  (`avatarTiming: "full"|"bookend"|"bookend-both"`, `avatarBookendSecs`, `avatarTailSecs`);
  layout defaults `scale 2.02 / offsetX 0 / offsetY 0.13` (`:1303-1305`).

**MCP orchestrator today (no avatar):** `src/lib/mcp/orchestrator.ts:32-92` runs
TTS → captions → keywords → stock → config → base render → create Video (`avatarModel:"none"` `:82`)

**service-auth seam** in `pipeline-client.ts` (`x-heroai-service-secret` + `x-heroai-act-as`).

only and has **no** avatar fields. Avatar is tracked separately on `Video.avatarVideoUrl`
(`prisma/schema.prisma:111`). No schema or renderConfig change is required.

**Risk #1 — RESOLVED:** all four avatar endpoints authenticate via
`getCurrentUser()` from `@/lib/clerk-auth` (the function that carries the service-auth seam
branch): `generate-with-bg:94`, `poll-avatar:23`, `composite:468`, `trim-audio:46`. So the
worker can call them headlessly through the **existing** seam — no auth changes needed.

## 1. Tool contract — new optional params on `create_video_job`

Added to `inputSchema` in `src/app/api/[transport]/route.ts` (all optional → full back-compat):

```ts
avatarMode?: "none" | "full" | "bookend" | "bookend-both"  // default "none"
avatarId?:   z.string()                                     // default user.heygenAvatarId
avatarIntroSecs?: z.number().int().min(1).max(30)           // default 5 (bookend & bookend-both)
avatarTailSecs?:  z.number().int().min(1).max(30)           // default 5 (bookend-both only)
```

- `avatarMode` (non-`none`) maps 1:1 to the web `avatarTiming` enum.
- Layout (scale/offset) is **not** a param — use web defaults as constants in `avatar-steps.ts`.

## 2. Gating (in the `create_video_job` handler, before enqueue)

When `avatarMode && avatarMode !== "none"`:
1. PRO/BUSINESS — unchanged global gate.
2. `!user.heygenKey` → `missing_key` for HeyGen. Add HeyGen to the onboarding copy
   (`src/lib/mcp/onboarding.ts` `PROVIDERS` + `missingKeyError`): label HeyGen, link to the
   HeyGen API-key page, paste at Settings → API Keys.
3. Resolve `avatarId = args.avatarId ?? user.heygenAvatarId`; if empty →
   `{ error: "missing_avatar", message: "ยังไม่ได้ตั้ง Avatar — ตั้ง heygenAvatarId ที่ Settings หรือส่ง avatarId มากับคำสั่ง" }`.
4. Persist `{ avatarMode, avatarId, avatarIntroSecs, avatarTailSecs }` into
   `VideoJob.inputJson` (via `createVideoJob` input) so the worker can read them.

Existing guards (Gemini key, Pexels/Pixabay key, clip quota, in-flight cap 3, idempotency)
are unchanged and still apply.

## 3. Orchestrator flow — `avatar-steps.ts`, sequential after base render

New module `src/lib/mcp/avatar-steps.ts` exposes one entry, e.g.
`runAvatarComposite(pc, { baseUrl, ttsAudioUrl, avatarMode, avatarId, introSecs, tailSecs })`,
returning `{ compositeUrl, avatarUrl, avatarTailUrl? }`. `pc` is the existing
`pipeline-client` (carries the service seam). Called from `orchestrator.ts` **only when**
`avatarMode !== "none"`, between base render and burn:

1. **Prepare avatar audio** (`/api/videos/trim-audio`):
   - `full` → use the full TTS `audioUrl` (no trim).
   - `bookend` → one trim call: **intro** (first `introSecs`) → `introAudioUrl`.
   - `bookend-both` → **two** trim calls: intro (first `introSecs`) and tail (last `tailSecs`)
     → two separate audio URLs (matches the web split path: intro and tail avatars are
     generated independently, not from a concatenated clip). The exact trim-audio params for
     "tail" are verified in the plan's first task.
2. **Generate** (`/api/heygen/generate-with-bg`, `audioUrl` = prepared audio, `avatarId`,
   `greenScreen: true`, layout defaults). `bookend-both` issues **two** generations
   (intro + tail).
3. **Poll** (`/api/videos/poll-avatar`) until `done`/`failed`, with a bounded timeout →
   `avatarUrl` (+ `avatarTailUrl`).
4. **Composite** (`/api/heygen/composite`, bg = `baseUrl`, `avatarTiming = avatarMode`,
   layout defaults, split for `bookend-both`) → `compositeUrl`.
5. Back in `orchestrator.ts`: **burn subtitles onto `compositeUrl`** (instead of `baseUrl`);
   set `Video.avatarModel = avatarId` and `Video.avatarVideoUrl = avatarUrl` on create/update.

When `avatarMode === "none"`: the current path runs **unchanged** (burn onto `baseUrl`).

## 4. Error handling & cost

- HeyGen generate/poll failure or poll timeout → job ends `failed` with a readable
  `errorMessage` (e.g. "avatar generation timeout — ตรวจ HeyGen key/avatarId/เครดิต"). The
  pipeline must **not** silently fall back to a no-avatar render. (`poll-avatar` already
  surfaces error states.)
- **Clip quota unchanged:** only base + burn reserve render clips (net 1/video); the avatar
  generation (external HeyGen, on the user's BYOK key) and the FFmpeg composite reserve
  nothing. Confirm `composite`/`trim-audio`/`poll-avatar` do not call `reserveClipUsage`.
- **Performance:** avatar jobs are heavier (HeyGen minutes + FFmpeg chromakey/concat) → longer
  wall-clock than the ~105s b-roll baseline. Use `chromakey` (default), never the `rembg`
  (Python) path. Expect to validate on the VPS (15 GB), not low-RAM local.

## 5. Risks / verification

- ✅ Service seam works for all four endpoints (verified — see Grounding).
- ⚠️ **Middleware/nginx passthrough:** today the worker only calls `/api/videos`
  (render/POST/PATCH). Verify the service-authed worker requests reach
  `/api/heygen/generate-with-bg`, `/api/heygen/composite`, `/api/videos/trim-audio`,
  `/api/videos/poll-avatar` (middleware allowlist + the nginx strip of the service headers).
  → **First task of the implementation plan.**
- ⚠️ Surface HeyGen credit/quota errors from the user's key clearly (BYOK).

## 6. Testing

- `scripts/verify-mcp-avatar-input.ts` — schema/gating: `avatarMode` validation, missing
  HeyGen key → `missing_key`, missing avatarId → `missing_avatar`, `avatarMode`→`avatarTiming`
  mapping, defaults/clamps for intro/tail secs. Pure (no DB; plain user-shaped objects).
- `scripts/verify-avatar-steps.ts` — `avatar-steps.ts` against a **mock** pipeline-client:
  assert the right endpoint calls per mode (full: no trim, 1 gen; bookend: trim intro, 1 gen;
  bookend-both: trim intro+tail, 2 gen, split composite) and that the burn target is
  `compositeUrl`.
- **Manual e2e** for all three modes on a real account with a HeyGen key (mirrors the
  2026-06-13 prod e2e). Final plan task; likely on the VPS.
